💡 Why this repo exists

Textbooks prove orderings — minimax Θ(√nk), asymptotic ΣΔ/d(μ,μ*) — but practitioners need constants at n≈10³–10⁴, which structure survives non-stationarity, and whether synthetic orderings persist on real data. This repo closes the loop theory → code → seeded benchmark → live walk-forward in one pinned, re-runnable place. It is a study guide that runs, a benchmark you can extend, and a template for honest market validation (costs, deflated Sharpe, regime notes, negative results included).

✨ Features — everything included

🎰 10 policies from theorems
ETC (+oracle m), UCB, UCB* (f(t)=1+t log²t), MOSS, KL-UCB (Bernoulli-KL bisection), Exp3 (loss-IX form), Exp3-IX, LinUCB/OFUL (ridge + √β‖a‖_{V⁻¹}), Phased-Elimination, Thompson Sampling (Beta–Bernoulli + Gaussian). Each docstring cites its equation.
🌍 4 environment families
Stochastic Bernoulli / Gaussian (gaps, subgaussian σ), oblivious + switching adversarial, linear hypercube / unit-ball, and live-market Bernoulli-ized assets. Lower-bound harnesses included.
🧪 Seeded benchmark harness
Fixed seeds, one action/step, 20 reps, mean±std + VaR95, pseudo-regret cross-check (ΣΔ·T), easy/hard splits that separate variance-aware winners.
📡 Live-market validation
Yahoo Finance + CoinGecko loaders, walk-forward folds, 5bps costs, Sharpe + deflated Sharpe, regime split, evidence CSVs. Dead sources (Stooq JS-wall, Binance geo-block) documented, not hidden.
🔎 Hidden-pattern studies
Variance trap · optimism failure · contrast memory · Exp3 tail — each a runnable script with a PhD-ready follow-up.
🐳 One-command reproduction
Pinned python:3.12-slim, frozen deps, docker compose up runs tests + all experiments. make test bench live for native runs.

🔎 Hidden patterns — the four findings

1 · Variance trap — Bernoulli(0.55,0.5): KL-UCB 17.4 vs UCB 44.5, UCB* 62.2. σ=1-UCB over-explores where Bernoulli variance peaks; KL's Δ²/2p(1−p) adapts. Follow-up: σ-free variance-adaptive UCB.
2 · Optimism failure — pulls [2028, 21, 951]: informative a2 gets 21 pulls vs 951 wasted on near-optimal a3. Optimism ≠ asymptotically optimal (Ch.25). Follow-up: optimal-design allocation.
3 · Contrast memory — level shift 0.3→0.6: absolute-memory TS stalls, sliding (contrast proxy) recovers and lands on the better arm ~2× more often. Follow-up: contrast-carrying TS for finance.
4 · Exp3 tail — Exp3 P95−P50 19.1 vs IX 16.5 at ≈equal means. Expectation hides risk; IX buys tail with bias. Follow-up: risk-aware adversarial bandits.
Bonus (Ch.31 reproduced): on the switching env, static regret goes negative (Exp3 −1477, IX −1888, UCB −2452 vs best-fixed) — tracking beats best-fixed, proving the static benchmark is meaningless under drift. Adversarial: stoch-like Exp3 104 vs UCB-misuse 95 (UCB “wins” only because the data is secretly IID — a misuse warning).

🔒 Live-market protocol (so reviewers trust it)

  • Assets→arms: large-cap equities (Yahoo) + BTC/ETH (CoinGecko). Reward 1{r_{t+1} > 5bps} (Bernoulli-ized, Ch.10 setting).
  • Walk-forward: 3–4 folds over 2y daily; decisions use only ≤t; hindsight best-asset only for scoring.
  • Costs/risks: 5bps/trade, Sharpe + deflated Sharpe (trials=10), hit-rate + regret + VaR.
  • Evidence: data/market_closes.csv, results/exp04_*.csv/json, exp04_meta.json (source + date + lookahead statement).
  • Caveats (stated): N≈500/fold (low power), 5 survivors (upward bias), no full multi-test correction, Bernoulli-ization drops magnitude. This validates the method, not an investment claim.
  • Source log (yfinance+coingecko): Yahoo + CoinGecko verified 2026-10-01; Stooq JS-wall and Binance geo-block documented as negative results.

🔌 API (30-second tour)

from bandit_lab.algos.kl_ucb import KLUCB
from bandit_lab.envs.stochastic import BernoulliBandit
import numpy as np
rng = np.random.default_rng(0)
env, pol = BernoulliBandit([0.7, 0.5]), KLUCB()
pol.reset(env.k)
for _ in range(1000):
    a = pol.select(rng); pol.update(a, env.pull(a, rng))   # select/update everywhere

from bandit_lab.algos.linucb import LinUCB
lin = LinUCB(d=5); lin.reset()
a = lin.select_arm(arms_matrix, rng); lin.update_ctx(arms_matrix[a], x)
